## The decision to make before rewriting anything

The original plan proposed moving chunk status out of `backlog.md` into YAML
frontmatter on each `docs/chunks/<ID>-*.md`, with the queue table generated by
`scripts/repo_state.py`. That was the multi-instance collision fix.

Decide this first and put the reasoning in the plan, because it determines
whether hand-grooming the queue table is worth doing at all. The honest state of
the evidence: there has been exactly one concurrent instance so far and zero
observed ledger collisions, so the migration may be solving a problem that has
not happened. Ben's standing preference is to ship rather than to build
machinery speculatively. A recommendation to defer is a legitimate answer;
silently doing neither is not.

The claim protocol is a separate, smaller question. `state/claims.json` exists
and `.claude/skills/dev-session/SKILL.md` already tells sessions to write a
claim, but nothing does. Either finish it or say plainly that it is unfinished.
